# CLAUDE.md — experimentation-analysis

## Purpose
Analyze the Hillstrom MineThatData e-mail experiment end to end: health checks, effect estimation, variance reduction, design/peeking, exploratory heterogeneity and a decision memo, on top of a small reusable stats library (`xpa`).
The contract is `docs/SPEC.md`. Read it at the start of every session, together with the top entry of `docs/HANDOFF.md`.

## Architecture map
- `src/xpa/config.py`: settings (`data_dir`, `seed`) via pydantic-settings; reads `.env`.
- `src/xpa/cli.py`: typer app (`xpa`).
- `src/xpa/data/`: download (bronze) and clean (silver). Writes to `data/` (gitignored, except `data/raw/MANIFEST.json`).
- `src/xpa/stats/`: library surface from the spec (`srm_test`, `diff_proportions`, `bootstrap_diff`, `cuped_adjust`, `power_two_proportions`, `simulate_aa`) — P1+.
- `src/xpa/eval/`: effect tables, report writers → `reports/results/*.json`, figures → `reports/figures/` — P1+.
- `docs/decisions/`: ADRs. `0001-metrics.md` is the pre-registration.
- `tests/`: no network; small synthetic fixtures in `tests/fixtures/`.

## Working rules (gate-based)
1. **Diagnose → propose → wait for approval → implement.** For any non-trivial change, first state what you found and a short plan (files, functions, tests). Stop and wait for "ok".
2. Stay within the current phase and `docs/SPEC.md` scope. Propose scope changes explicitly; don't implement them unasked.
3. Tests first for stats functions. Compare against `scipy` / `statsmodels` or closed-form values.
4. **Pre-registration discipline:** metrics and comparisons are fixed in ADR 0001. Don't look at outcome differences between arms before the phase that estimates them (Phase 2). Changing a metric or comparison requires a new ADR that supersedes 0001 and says why.
5. **No p-hacking:** every family of tests gets a multiplicity correction (Holm). Heterogeneity work (Phase 5) is labeled exploratory everywhere it appears. Report null results.
6. **Reproducibility:** every random process takes an explicit seed (default from config). Results in `reports/results/` are generated by code, never edited by hand.
7. Fixtures are synthetic. Never copy real dataset rows into the repo; the dataset is fetched by `xpa download`, not redistributed.
